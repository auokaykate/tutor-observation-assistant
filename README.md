# AI-помощник тьютора: анализ наблюдений за детьми с ОВЗ

Тестовое задание для Data Science разработчика. Модуль обрабатывает
записи тьютора в свободной форме:

- `extract(text)` — извлекает дату, ID ребёнка, автора, длительность сна
  и явно указанную зону (Часть 1);
- `classify(text)` — определяет тип записи: observation, lesson_report,
  parent_note, recommendation или unknown — и уверенность (Часть 2);
- `check_zone(note)` — решает, относится ли наблюдение к отслеживаемым
  зонам развития, и объясняет вывод (Часть 3).

Всё работает детерминированно, без ключей и сети. LLM для Части 3
подключается по желанию. Результаты прогона и обоснование решений —
в [RESULTS.md](RESULTS.md).

## Установка

Нужен Python 3.11 или новее.

```bash
python -m pip install -r requirements.txt
```

Используется `python -m pip`, потому что на Windows `pip` может не быть
в PATH. Пакет `anthropic` нужен только для LLM-режима: без него всё
работает на правилах.

## Тесты

```bash
python -m pytest -v
```

Покрыты:

- все форматы дат и длительности сна;
- нормализация ID ребёнка;
- автор;
- отсутствие зоны в R4 и пустые поля R6;
- порог unknown и правило его подбора;
- все 15 наблюдений на fallback;
- переходы на правила без ключа, при неверном ключе, без сети и при ответе
  неверного формата;
- отсутствие в объяснениях чисел, которых нет в тексте;
- флаги постконтроля;
- актуальность `output/report.md` и `RESULTS.md`.

Для LLM-тестов поднимается локальный HTTP-сервер, внешняя сеть не нужна.

## Запуск

```bash
python main.py
```

Одна команда прогоняет `dataset.json` через все три части и пишет:

- `output/results.json` — полный структурированный результат со скорами,
  уверенностью и флагами;
- `output/report.md` — таблицы по всем частям;
- `RESULTS.md` — собирается скриптом из `output/report.md` и шаблона
  `tutor_assistant/results_template.md`; числа вручную не вписываются.

Параметры: `--dataset`, `--expected`, `--output-dir`, `--results-md`,
`--llm` (подробнее: `python main.py --help`).

Пример использования из кода:

```python
>>> from tutor_assistant import check_zone, classify, extract
>>> extract("05.03.2025. Ребёнок CH-0421, тьютор Иванова А. С. Сон 6 ч 30 мин")
{'date': '2025-03-05', 'child_id': 'CH-0421', 'author': 'Иванова А. С.', 'sleep_hours': 6.5, 'zone': None}
>>> classify("Рекомендация от 12 марта 2025 г.: ввести сенсорную паузу.")
('recommendation', 0.95)
>>> check_zone("отказ от еды третий день подряд")
(True, 0.76, "Отказ от еды относится к зоне 'питание' (в записи: «отказ от еды третий день подряд»).")
```

### LLM-режим

```bash
python main.py --llm
```

В этом режиме `check_zone` сначала спрашивает модель `claude-opus-5-5`
через Anthropic SDK. Нужен ключ в переменной окружения
`ANTHROPIC_API_KEY`. Ответ запрашивается по JSON-схеме (structured
outputs) и принимается только после проверки формата: зона из списка,
уверенность от 0 до 1, объяснение называет зону и не содержит чисел,
которых нет в тексте наблюдения. При отказе модели по политике
безопасности API переключается на резервную модель
(`fallbacks: "default"`).

Если что-то не так — нет пакета, ключа или сети, неверный ключ, отказ
модели, ответ не того формата — функция молча переходит на правила.
Источник каждого ответа (`rules` или `LLM`) виден в отчёте.

**С реальным ключом LLM-режим не проверялся: ключа не было.** Проверено
тестами на локальном сервере:

- настоящий SDK отправляет запрос и разбирает корректный ответ;
- при неверном ключе (401), недоступной сети, отсутствии ключа и ответах
  неверного формата используются правила.

## Архитектура

```
main.py                     CLI: прогон датасета и запись отчётов
tutor_assistant/
    config.py               пороги, веса, словари, форматы дат, настройки LLM
    text.py                 нормализация текста, фрагменты, числа
    extract.py              Часть 1: extract()
    classify.py             Часть 2: classify()
    zones.py                Часть 3: check_zone() — правила, LLM и fallback
    llm.py                  вызов Anthropic SDK и проверка ответа модели
    pipeline.py             прогон датасета, сверка с разметкой, флаги
    report.py               output/report.md и сборка RESULTS.md
    results_template.md     текст RESULTS.md без чисел
tests/                      pytest-тесты
dataset.json                данные из Приложения 1
expected.json               ручная разметка ожидаемых ответов
output/                     results.json и report.md последнего прогона
```

Поток данных: текст → `classify` (тип записи) → `extract` (поля) →
`check_zone` (зоны развития) → флаги постконтроля → JSON-отчёт с
уверенностью.

- **Часть 1** — регулярные выражения и правила из конфига. Ненайденное
  поле равно `None`.
- **Часть 2** — взвешенные ключевые слова и доли скоров. Если разрыв
  первого и второго места меньше `UNKNOWN_GAP_THRESHOLD`, возвращается
  `unknown`.
- **Часть 3** — признаки зон с весами. Конкурирующая зона и ситуативное
  обстоятельство снижают уверенность ниже `LOW_CONFIDENCE_THRESHOLD`.

Флаги считаются отдельно:

- «требуется уточнение» — запись не понята;
- «низкая уверенность» — ответ есть, но уверенность ниже порога.

Все пороги, веса и словари лежат в `tutor_assistant/config.py`.

## Данные

- `dataset.json` — Приложение 1 из PDF: записи R1–R6 и 15 наблюдений.
  Тексты перенесены символ в символ. Переносы строк из вёрстки PDF
  заменены пробелами, «CH0107» записан без дефиса.
- `expected.json` — ручная разметка ожидаемых ответов. Нужна для сверки в
  отчёте и тестах, частью исходных данных не является.
